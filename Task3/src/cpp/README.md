# RSA-OAEP padding experiment

This directory adds an OAEP padding layer on top of the textbook RSA code in `../../../Task1/src/cpp`.

## Build

```bash
make
```

The programs use the RSA key files generated by `Task1/src/cpp/keygen`.

## Encoding and encryption

```bash
./OAEP_encoding "hello" 512 64 ../../../Task1/RSA_Public_Key.txt
```

If `k0` and `k1` are omitted, they default to `512` and `64` bits. An optional trailing argument selects the hash (`sha256` or `sha512`, default `sha512`). The program prints the random string `r`, the left block `X`, the right block `Y`, the OAEP encoded message `X || Y`, and the RSA ciphertext.

The implemented OAEP encoding is:

```text
X = (m || 0^k1) xor G(r)
Y = r xor H(X)
OAEP(m) = X || Y
```

`G` and `H` are implemented with MGF1 over the selected hash (SHA-512 by default), using different labels for domain separation.

## Decoding and decryption

```bash
./OAEP_decoding <ciphertext_hex> 512 64 ../../../Task1/RSA_Secret_Key.txt
```

The decoder first computes the RSA plaintext representative, splits it as `X || Y`, then reverses OAEP:

```text
r = Y xor H(X)
m || 0^k1 = X xor G(r)
```

It rejects invalid padding when the recovered `k1` trailing bits are not all zero.

Run the bonus demonstration with a ciphertext produced by `OAEP_encoding`:

```bash
./OAEP_cca2_demo <ciphertext_hex> 512 64
```

The program creates the same style of multiplicative forged ciphertext used in the textbook RSA CCA attack, then sends it to the OAEP decoder. The expected result is an OAEP padding rejection.
