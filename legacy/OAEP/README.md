# RSA-OAEP padding experiment

This directory adds an OAEP padding layer on top of the textbook RSA code in
`../textbook-rsa`.

## Build

```bash
make
```

The programs use the RSA key files generated by `../textbook-rsa/keygen`.

## Encoding and encryption

```bash
./OAEP_encoding "hello" 128 128 ../textbook-rsa/rsa_public_key.txt
```

If `k0` and `k1` are omitted, both default to `128` bits. The program prints
the random string `r`, the left block `X`, the right block `Y`, the OAEP encoded
message `X || Y`, and the RSA ciphertext.

The implemented OAEP encoding is:

```text
X = (m || 0^k1) xor G(r)
Y = r xor H(X)
OAEP(m) = X || Y
```

`G` and `H` are implemented with MGF1 over SHA-256, using different labels for
domain separation.

## Decoding and decryption

```bash
./OAEP_decoding <ciphertext_hex> 128 128 ../textbook-rsa/rsa_private_key.txt
```

The decoder first computes the RSA plaintext representative, splits it as
`X || Y`, then reverses OAEP:

```text
r = Y xor H(X)
m || 0^k1 = X xor G(r)
```

It rejects invalid padding when the recovered `k1` trailing bits are not all
zero.

## Why RSA-OAEP is better than textbook RSA

Textbook RSA is deterministic: the same plaintext always produces the same
ciphertext. It is also multiplicatively malleable, because an attacker can
transform a ciphertext `c = m^e mod N` into `c * s^e mod N`, which decrypts to
`m * s mod N`. That property is the basis of the CCA attack shown in the
textbook RSA experiment.

RSA-OAEP adds randomized padding before RSA encryption. The random `r` makes
two encryptions of the same message produce different ciphertexts. The two
blocks are also coupled: `X` is needed to recover `r` from `Y`, and `r` is
needed to recover `m || 0^k1` from `X`. A change in any bit of `X` changes
`H(X)`, and a change in `r` changes `G(r)`, so partial recovery or controlled
modification is no longer useful.

For the CCA2 attack from textbook RSA, the forged ciphertext usually decrypts
to a random-looking OAEP block whose recovered padding does not end in `k1`
zero bits. The OAEP decoder rejects it instead of returning a related plaintext,
so the multiplicative chosen-ciphertext attack is thwarted.

You can run the bonus demonstration with a ciphertext produced by
`OAEP_encoding`:

```bash
./OAEP_cca2_demo <ciphertext_hex> 128 128
```

The program creates the same style of multiplicative forged ciphertext used in
the textbook RSA CCA attack, then sends it to the OAEP decoder. The expected
result is an OAEP padding rejection.

This implementation is for the experiment. A production RSA-OAEP implementation
should use a vetted cryptographic library and constant-time error handling.
